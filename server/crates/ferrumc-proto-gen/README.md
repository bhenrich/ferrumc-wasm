# ferrumc-proto-gen

Build-time code generator for the Minecraft 1.21.8 (protocol 772) packet layer.

This crate is **not** a runtime dependency of `ferrumc-proto` and never ships in
the server binary. It is driven exclusively by `cargo xtask generate`, which
writes deterministic, checked-in Rust into
`crates/ferrumc-proto/src/generated/`. There is no dependency cycle: the
direction is `xtask -> ferrumc-proto-gen -> (writes files into) ferrumc-proto`.

## Commands

- `cargo xtask generate` — regenerate the checked-in protocol code in place.
- `cargo xtask generate --check` — regenerate in memory and fail (non-zero exit
  plus a diff) if the committed files have drifted. CI runs this.

Both commands share a single emit path, so `--check` can never disagree with
what `generate` would write.

## Determinism

Generated output must be byte-identical across machines and runs:

- The pinned spec is the vendored `fixtures/protocol/1_21_8/manifest.toml`;
  generation aborts if its protocol/data versions are not `772` / `4440`.
- Files are emitted into a `BTreeMap` (sorted, no map iteration order leaks).
- Every `.rs` file is normalized through the real `rustfmt` (pinned via
  `rust-toolchain.toml`) — never hand-formatted.
- Output is forced to LF line endings with a single trailing newline, and
  `.gitattributes` marks the generated directory `eol=lf`.
- No timestamps, absolute paths, or usernames are ever written into output.

Every generated file carries the header
`// @generated by ferrumc-proto-gen. Do not edit by hand.` followed by a source
pin line naming the vendored `minecraft-data` commit.
