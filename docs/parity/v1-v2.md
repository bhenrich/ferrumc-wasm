# FerrumC v1 → v2 Parity Audit

> Honest, skimmable comparison of the legacy **v1** server (`ref/` — Bevy ECS + LMDB +
> DashMap) against the **v2** rework (this repo — actor-sharded sim + redb behind traits).
> Both target **Minecraft Java 1.21.8 / protocol 772**.
>
> v2 status is grounded in [`../FEATURES.md`](../FEATURES.md), [`../ROADMAP.md`](../ROADMAP.md),
> [`../public-alpha.md`](../public-alpha.md), and the code. v1 status is grounded in `ref/`'s
> own self-audit (`ref/docs/vanilla_parity_feature_list_aggregations_todolist.md`), its README,
> and the crate/packet/system surface in `ref/src/`.
>
> Legend: **✅ present** · **🟡 partial** (wired but incomplete / buggy / inert) · **❌ absent**.
> No performance claims are made here — neither codebase has published benchmarks.

## 2. Public-Alpha Blockers Still Open (v2)

Cross-referenced against `../public-alpha.md` unchecked items. None of these are "missing features" so much as **missing proof and polish** before a credible public alpha:

- **Fresh-clone build verification** — `[ ] Fresh clone builds` is still unchecked; there's no recorded "git clone → `cargo build` → green" run. (Cannot self-verify here; cargo is not to be run.)
- **Real-client smoke checklist** — `[ ] Real-client smoke checklist documented` + `[ ] Strict raw-wire trace for critical packets`. The FEATURES test steps exist but aren't consolidated into a signed-off smoke run.
- **Benchmarks published** — the entire Performance section is unchecked (startup / join-storm / movement / active-builder / plugin-overhead), and results must include commit SHA + hardware. `docs/benchmarks/` is a README only.
- **Persistence test coverage** — `[ ] Persistence tests cover pinned chunks`, `[ ] Dirty state/journal path has metrics`, `[ ] Reject/resync behavior tested for invalid placement`.
- **Rejoin-persistence inconsistency** — FEATURES claims the spawn-area rejoin bug is fixed; ROADMAP "Next" still lists it as open. Resolve and confirm on a real client before alpha.
- **Wire the serverbound packet budget** — built but never constructed; the play loop is currently unbudgeted (a hardening gap, not strictly an alpha gate, but cheap and listed).

Already green (for reference): no-config safe start, offline join, two-client visibility/movement/rotation/block-changes, held-item, creative placement, basic block states, leave/rejoin + restart persistence, plugin Replace, dashboard, no unbounded channels, no `unwrap` outside tests, `xtask generate --check`.

## 3. v1 Features NOT Worth Copying to v2

These are architectural cul-de-sacs or things v2 deliberately rejected — porting them would fight the rework's own rules.

- **Bevy ECS global world.** v2's whole thesis is actor-sharded, lock-free, message-passing simulation (ADR-0002, CLAUDE.md bans "Global ECS world"). Copying Bevy reintroduces the shared-world model the rework exists to escape.
- **`DashMap` + `WyHash` concurrent chunk cache + Moka.** v2 owns chunks per-shard; a global concurrent map is the exact pattern CLAUDE.md calls out as "solving the wrong problem."
- **Burst tick catch-up (`MissedTickBehavior::Burst`, up to 5 missed ticks).** v2 policy is explicitly *never* run catch-up ticks — under load that converts lag into collapse. Direct anti-pattern.
- **Global mutable state via `OnceCell`/statics** (`get_global_config()`, `static WHITELIST`, `set_global_config`). v2 forbids global mutable state; config/state flow through arguments and channels.
- **Monolithic `src/bin` packet-handler + system soup.** Handlers, ECS systems, and game logic live together in the binary; v2's lane separation (net → session → sim → storage) is cleaner and shouldn't be undone.
- **The `ferrumc-plugins` crate.** It's a placeholder stub (`add(2,2)`). Nothing to port — v2's plugin host is already far ahead.
- **Half-wired-but-inert survival scaffolding** (pig bundle with no AI, `Health`/`Hunger`/`Experience`/`ActiveEffects` components with no tick logic, crafting handler with no recipe engine). Copying dead component shells just imports tech debt; v2 should build survival deliberately when it gets there.
- **Dashboard exposed beyond loopback with a shared `secret`.** v2 chose loopback-only + read-only + GET-only by construction, which is a stronger default security posture than a bind-anywhere dashboard guarded by a config secret.

## 4. Worth Stealing From v1

Concrete, portable wins that don't violate v2's architecture:

- **Working Anvil import pipeline** (`ref/src/lib/world/src/importing.rs` + `vanilla_chunk_format.rs`, memmap2 + rayon + `indicatif` progress). v2's `ferrumc-anvil` is a skeleton and Anvil import is the #1 roadmap persistence item — the conversion logic and chunk-format mapping port almost directly into `ferrumc-anvil`/`ferrumc-world`.
- **`assets/extracted/` vanilla data dump** — `blocks.json`, `items.json`, `recipes.json`, `enchantments.json`, `structures.json`, `multi_noise_biome_tree.json`, `density_function_tests.json`, `carver.json`, `game_rules.json`, `damage_type.json`, etc. A ready-made 1.21.8 data corpus for v2's registry/terrain/survival roadmap (feed the generator, don't hand-edit generated output).
- **Online-mode auth reference** (`ref/src/lib/net/auth.rs` + `encryption` crate: RSA-1024, AES-128-CFB8, `hasJoined` digest). v2's online-mode roadmap item can lift the crypto/handshake approach wholesale; it's clean-room-able.
- **LAN broadcast pinger** (`systems/lan_pinger.rs`, UDP 224.0.2.60:4445) — tiny, self-contained, makes the server show up in the client's LAN list. Cheap win.
- **Day-night cycle** (`systems/day_cycle.rs` + `update_time` packet) — small, isolated, visibly improves "feels alive" with no survival dependencies.
- **Dashboard system metrics** (CPU/RAM/uptime/storage via sysinfo, `dashboard/telemetry.rs`) — v2's dashboard has richer app pages but no host metrics; this is an additive panel.
- **Tracy profiling integration** (`--features tracy`) — a profiling on-ramp v2 lacks; useful before publishing the benchmarks the alpha checklist demands.
- **Branding assets** (`ref/assets/data/icon.png`, `icon-64.png`, README banner/header.svg) — reusable server-list favicon and repo branding so v2 doesn't start from a blank icon.
